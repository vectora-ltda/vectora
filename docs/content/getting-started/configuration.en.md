## Where the data lives

Everything Vectora needs to run lives in `~/.vectora/`:

```text
~/.vectora/
├── config.toml             # runtime configuration (providers, storage)
├── auth.key                # JWT key (auto-generated, 600 permissions)
├── data/
│   ├── vectora.db          # users, sessions, memories, checkpoints (SQLite WAL)
│   ├── embedding_queue.db  # async indexing queue
│   ├── traces.db           # observability spans
│   └── lancedb/            # vector store (lite mode)
├── artifacts/              # plans/specs generated by the agent
├── secrets/
│   ├── system.kdbx         # system secrets vault (KeePassXC)
│   └── users/{id}.kdbx     # per-user vault (API keys, SSH)
├── skills/{user_id}/       # installed skills (SKILL.md)
├── safe_roots.json         # trusted paths configured by the admin
└── workspaces.json         # registered workspaces
```

## Environment variable hierarchy

Three layers, most specific wins:

```text
defaults.env (built into the app)  →  .env (project, dev)  →  ~/.vectora/.env (user, global)
```

Per-user overrides (e.g., a different API key for one team member) live in the `env_overrides` database column, editable via **Settings → Environment → Envs**.

## Storage mode: lite or complete

Controlled by `STORAGE_MODE` (`lite` by default). See the dedicated guide at [Storage: lite vs. complete](../../concepts/storage) to know when each makes sense — quick summary: **lite** (SQLite + LanceDB) is zero-infra and handles real scale; **complete** (Postgres + Qdrant + Redis) is about durability/managed infra, not a performance gate. Regardless of mode, users/auth/config always stay in SQLite.

## Settings categories

Settings are organized by scope and capability. **Preferences** contains personal options; **Environment** contains AI providers, routing, variables, skills, MCP plugins, and integrations; **Administration** contains instance controls. Availability depends on the user's role. See [Using settings](../../guides/using-settings) for details.
